# 虛擬用戶：價格敏感度測試

對 Oingg 付費方案做價格敏感度測試（Van Westendorp PSM、Gabor-Granger）用的虛擬用戶（synthetic personas）。所有人物、金額與持股比重都是虛構的，不對應任何真實個人。

> 這份資料**不寫進 DB**：`users` 表是正式用戶資料，之前放進去的 demo 資料也被要求移除過（見 `prisma/seedPresetTemplates.ts` 開頭的註解）。persona 只當研究素材用。

## 三批資料，性質不同

| 檔案 | 人數 | 怎麼來的 | 拿來做什麼 |
|---|---|---|---|
| `retiree-personas.json` | 12 | 手寫，維度刻意拉開 | 主樣本。分群曲線、對照組、方案結構測試都靠這批 |
| `extended-personas.json` | 8 | 手寫，補**決策情境** | 補第一批涵蓋不到的情境，不是加更多退休族 |
| `sampled-personas.json` | 60 | 由 `generate-sampled-personas.mjs` 從五大人格分布抽樣 | 提供輸入的變異與「平凡的中間值」 |

**Schema 不是三批都一樣，接的時候要分開處理：**

- 第一、二批同構，唯一差別是在職者用 `occupation`，退休者用 `formerOccupation` + `retiredForYears`。
- 第三批是另一種東西。它**沒有** `name`／`household`／`currentToolSpend`／`oinggFit`／`purchaseBehavior`／`rolePlayNotes`／`priceSensitivityHypothesis`，改成 `traits`（五大人格分數）、`billing`、`affordableMonthlyTwd`。所以它跑不了需要角色扮演口吻或參考價錨點的題目，適合的是數值型的願付價格分布。

榮格／MBTI 側寫的位置也分三種：第一批寫在 `persona-cognitive-profiles.md`（不在 JSON 裡），第二批在各自的 `cognitive` 欄位（MBTI 類型 + 主導／劣勢功能 + 壓力下的切換 + 判斷依據），第三批只有 `traits` 的五個數值、沒有 MBTI。

**第二批補的是情境不是人數。** 手寫 persona 的盲點是作者只寫得出「有特色」的人，而第一批 12 位全是自己做決定的退休族本人。ext-01 是手上有 28 位客戶的獨立財務顧問（B2B 需求）、ext-03 是替母親付費與操作的兒子（付費者不等於使用者）、ext-05 是在職且同時照顧父親——每一位對應一個原本零覆蓋的決策情境，理由寫在各自的 `priceSensitivityHypothesis.rationale`。

**第三批是抽樣，不是更多手寫。** 真實母體大部分平凡，而平凡的那一段恰好決定營收。用它產生**輸入**的變異，**不要用它宣稱輸出的效度**——LLM 扮演時仍會往平均回歸。腳本開頭把每個參數標了實證／近似／假設三級，任何依賴那些係數精確值的結論都不成立。

測試時特別值得看的對照：

- **01 vs 09**：資產相近，但一個有終身月退、一個「只出不進」，看心理帳戶對價格的影響。
- **04 / 08**：付費者不等於使用者（子女決定），是價格帶的下緣。08 是對照組，模擬出來如果她願意付高價，就代表模擬有偏誤。
- **03 / 12**：「太便宜」門檻應該明顯偏高，可以驗證價格作為品質訊號的效果。
- **05**：參考價是投顧年費，看純資料工具的價值能不能被接受。
- **06 / 07**：適合測方案結構，例如單一功能方案、年繳、買斷、不自動續約。
- **10 / 11**：適合測團體／家庭方案，以及促銷（首月優惠）的效果。

## 欄位說明

| 欄位 | 說明 |
|---|---|
| `income.sources[]` | 每月收入來源與金額（TWD），股利這類年收入已攤成月 |
| `income.monthlyLivingExpenseTwd` | 每月生活開銷，和收入相減就是可支配餘裕 |
| `assets.portfolio[]` | 持股代號與約略比重（%），只用來描述風格，不含股價 |
| `investing.riskTolerance` | 1（極保守）–5（積極） |
| `digital.techLiteracy` | 1（只會 LINE 看照片）–5（自己寫爬蟲） |
| `currentToolSpend[]` | 目前在投資資訊上的月支出，是**價格錨點**的主要來源 |
| `oinggFit.featuresOfInterest` | 對應到 Oingg 現有功能（除權息行事曆／公告、特別股頁、ETF 篩選與排行、選股範本、持股管理、交易日誌、各類排行、個股財報／杜邦／Piotroski 等） |
| `purchaseBehavior` | 誰做決定、偏好的付款週期、試用期待、主要抗拒理由 |
| `rolePlayNotes` | 給 LLM 角色扮演用的說話風格 |
| `values` | Schwartz 10 個基本價值的**排序**，附 `top3` / `bottom2` 與判斷依據。手寫的 20 位是逐句找證據排的（`evidence`），抽樣的 60 位由 `traits` 推導（`derivedFrom: "traits"`）——兩種可信度不同，見 `persona-cognitive-profiles.md` §8 |
| `priceSensitivityHypothesis` | **設計者的假設，不要餵給受測模型**，只用來事後比對結果 |

## 建議測試流程

### 1. 角色扮演 prompt 範本

把 persona JSON **拿掉 `priceSensitivityHypothesis`** 之後放進 system prompt：

```
你現在是以下這位台灣退休族，請完全以他／她的身分、收入狀況、說話方式回答。
不知道的事就照這個人會有的反應回答，不要跳出角色，也不要給「理性消費者」式的標準答案。

<persona>
{persona JSON，已移除 priceSensitivityHypothesis}
</persona>

<product>
{Oingg 付費方案的功能說明：包含哪些功能、跟免費版差在哪裡。不要寫價格}
</product>
```

### 2. Van Westendorp PSM（4 題，開放式回答金額）

每位 persona 都問同樣的 4 題、同樣的順序，單位固定為「新台幣／月」（要測年繳就另外跑一輪，單位改成「／年」）：

1. 這個方案每月多少錢，你會覺得**太便宜**，便宜到懷疑它的品質？
2. 每月多少錢，你會覺得**很划算**，是物超所值的好價格？
3. 每月多少錢，你會開始覺得**有點貴**，但還是會考慮？
4. 每月多少錢，你會覺得**太貴**，完全不會考慮？

把 4 條累積分佈曲線畫出來，找出 PMC、OPP、IPP、PME 四個交點，就是可接受價格區間。

### 3. Gabor-Granger（驗證特定價格點）

依 PSM 得到的區間取 4–5 個價格點（例如 NT$99／149／199／299／399），**隨機順序**逐一詢問「這個價格你會訂閱嗎？」（1–5 分購買意願），就能算出需求曲線和營收最大化的價格。

### 4. 方案結構（選做）

針對 06、07、10、11 追問：月繳 vs 年繳（打 8 折）、單一功能方案、家庭／團體方案、首月優惠、不自動續約，各自會讓接受度怎麼變。

## 使用 LLM 模擬受測者的注意事項

- **每位 persona 至少跑 20–30 次**（temperature 約 0.7–1.0）再取分佈，不要只看單次回答。
- PSM 的 4 題維持固定順序；**Gabor-Granger 的價格點順序要隨機化**，降低錨定效應。
- 研究普遍指出，LLM 模擬的受測者價格敏感度**通常比真人低**，回答也比較「理性、一致」。結果只適合做**方向判斷和挑出價格區間**，正式定價前仍建議找真實退休族做小規模訪談或問卷校正。
- 用 `priceSensitivityHypothesis` 做健全性檢查：如果 08 的「太貴」門檻比 03 還高，就代表 prompt 或模型有問題。
- **塌縮檢查一定要做**：合成受測者會大量回歸到同一個「模態答案」。跑完先看回答的離散程度，如果大部分 persona 給出幾乎一樣的數字，那是模型塌縮不是共識，該批結果要丟掉重跑。第三批 60 位存在的意義正是讓這件事看得出來——輸入夠分散時，輸出還是擠在一起就藏不住了。
