## 一句話結論

- 付費牆依法只能鎖三件事：查詢廣度、歷史深度、匯出／推播。目前**只有「查詢廣度」真的在運作**。
- **還沒有做：** 金流、電子發票、提醒信、匯出、推播。
- **歷史深度無貨可賣：** 上游資料對所有人都只有約 24 季。
- **conductor 的幾份舊文件還在鎖分析內容**，這跟投信投顧法的界線衝突。照那些文件動工之前，要先把文件改掉。

## 二、待做：金流與訂閱生命週期（Phase 1）

**卡在：** 正式環境的公開 HTTPS 網址，藍新付款完成後要回呼這個網址。所以這一整段要等正式環境部署之後才能做。

| # | 項目 | 負責 | 要點 | 來源 |
|---|---|---|---|---|
| 1 | 藍新結帳 | bff-ts＋web-nuxt | 信用卡定期定額（`/MPG/period`）**只支援信用卡**。ATM／超商年繳只能走一次性 MPG 付款，沒有自動續約，所以要搭配提醒信 | [LC] §1、[BFF] §8 |
| 2 | 付款回呼（NotifyURL） | bff-ts | 冪等鍵 `(PeriodNo, AlreadyTimes)`；簽章不符一律拒絕；不信任回呼帶來的金額；不記錄 HashKey/HashIV；不受全站每分鐘 300 次限流影響 | memory phase0 |
| 3 | 寫入訂閱資料 | bff-ts | 目前訂閱資料只能手動建立。要補 `currentPeriodStart`（或 `lastPaidAt`）：七天退費從**這一期的付款時間**起算，不能用建立時間，否則第二年續約的人永遠退不了費 | [LC] §5–6 |
| 4 | 退費流程 | bff-ts | 七天無條件退費**已定案**，流程本身還沒做 | [LC] §5 |
| 5 | 排程器 | bff-ts | Cloud Scheduler＋OIDC 私有端點，負責到期降級與寄提醒；提醒紀錄用 append-only 的 `SubscriptionReminder(firebaseUid, kind, sentAt)`，不要在訂閱表上開布林欄位 | [BFF] §8、[LC] §6 |
| 6 | 提醒信 | bff-ts | 節奏已定：一次性年繳到期前 30／7／1 天；定期定額扣款前 7 天。寄信元件已就緒，接上排程即可。**試用到期提醒的時間點還沒定**（見第九節） | [LC] §2 |
| 7 | 定期定額的寬限期 | bff-ts | 扣款失敗後寬限 7 天並重試；一次性年繳不設寬限 | [LC] §3 |
| 8 | 拿掉開發用白名單 | bff-ts | 環境變數 `BILLING_PAID_UIDS` 是金流上線前的暫時替代品，金流上線那天刪掉 | memory phase0 |
| 9 | 正式環境前置 | bff-ts | `FILTERS_SERVICE_URL` 改 https；寄信服務金鑰 `RESEND_API_KEY` 換新 | memory pre-deploy |

## 四、待做：匯出／推播（第二個合法的收費槓桿，完全沒做）

目前推動付費的只有「自選股 10 檔」這條線。這一類是唯一還能合法加進 PRO 的東西。

| 項目 | 文件規劃 | 來源 |
|---|---|---|
| 選股結果匯出 CSV/Excel | PRO | [P] 2.2、[SCR] §1 |
| 持股匯出 CSV/PDF | PRO | [P] 二之一 |
| 自選股版面匯出 CSV | PRO | [WL] §2.1 |
| 個股頁匯出 CSV/PDF | PRO | [P] 2.2 |
| 除權息提醒 | PRO。訪談裡有一位受訪者**唯一的付費理由**就是這個 | [R06] §2、[PP] |
| 選股條件新符合提醒 | PRO | [P] 2.2 |
| 自選股事件推播 | PRO | [P] 2.2 |

規則：
- **推播預設關閉**，只由事件觸發（[GD]）。
- **降級時**暫停寄送、保留設定（[E] §3.2）。
- **匯出檔**加一欄資料日期（knowledgeDate），並提供列印樣式：A4、不跨頁斷行、黑白可讀（[PP]）。
- **⚠️ 合規：** 推播與匯出的內容只能是資料與事件（「2330 明天除息」），**不能是選股結論或評等**。帶有推薦的通知等於收費提供分析意見，構成投信投顧法第 4 條要件。
  - 做法：比照寄信元件，用列舉的通知種類來防，不開放自由文字。

負責：
- **bff-ts：** 產生檔案、排程、寄送。
- **web-nuxt：** 介面。
- **你決定：** 哪幾項放進 PRO、先做哪一項。

## 七、不做（無貨可賣）：歷史深度

- 上游的季度指標對所有人都只有約 24 季，月營收 60 個月，**沒有更深的資料可以賣給 PRO**（[HIST]、`quota.ts` 註解）。
- 約 23% 的公司連 24 季都沒有，主因是 mops 上游那幾季就沒有資料。
- 如果哪天要賣這個維度，結帳頁必須逐檔標示**實際**有幾季。寫「解鎖更長歷史」而實際上給不出來，會被當成不實陳述；這可能引發七天退費，也可能被公開抱怨。
